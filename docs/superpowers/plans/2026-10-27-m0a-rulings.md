# M0a — rulings made during subagent-driven execution

These are the decisions the controller made on your behalf while it ran plan
`docs/superpowers/plans/2026-10-27-m0a-core-local-imap-smtp.md`. They are listed
in the order they were made. Each line says what was decided, why, and what it
costs if it was wrong. Review them, and reopen any you disagree with.

33 early rulings (mostly in the MIME, HTML-cleaning and IMAP tasks) were
recorded without a cost line. They are implementation choices made while
fixing task-review findings, and each one was checked by that task's re-review.

- Ruling A: `outbox.Enqueue` gains a `draft mail.Ref` parameter (empty when not sending a draft), stored with the item, and `outbox.Sender` gains the same parameter. The Sender (built in T27) sends, then calls `DiscardDraft` when the ref is non-empty; a discard failure is logged by error code and does not fail the send. T22 passes the draft ref instead of discarding itself. — Why: with an undo window the send happens in the worker, so only the worker knows when it succeeded; discarding at enqueue time would trash a draft the user may still cancel. — Cost if wrong: a small signature change in T19/T22/T27.
- Ruling B: the principal reaches tool handlers like this. `mcpserver.Options` gains `Principal func(ctx context.Context, req *mcp.CallToolRequest) (service.Principal, error)`, and `safe(...)` puts the result into ctx with `service.WithPrincipal` before calling the handler. stdio (T27) returns the fixed local principal. HTTP (T25) uses the SDK's `auth.RequireBearerToken` with a `TokenVerifier` backed by `tokens.Manager`; `TokenInfo.UserID` = tenant ID and `TokenInfo.Scopes` = token scopes; the HTTP principal function reads `req.Extra.TokenInfo`. Local tokens have no expiry, so set the SDK option that allows a missing expiration (`AllowMissingExpiration`, added in go-sdk v1.8 [verify]) or a far-future expiration if that option is absent. — Why: the SDK carries auth info to handlers through `req.Extra.TokenInfo`; relying on the HTTP request ctx reaching handlers is not documented. — Cost if wrong: rework in T23/T25/T27 wiring only.
- Ruling C: T27 builds the outbox Sender as a closure over the store and the BackendFactory (load account by tenant+id, get its backend, Send, then DiscardDraft per Ruling A). The Service is not involved. — Why: the outbox must exist before the Service, and the Sender only needs the factory. — Cost if wrong: none beyond wiring.
- Ruling D: the Docker image's default CMD is `["serve"]` (stdio, used with `docker run -i` from a harness config). HTTP inside a container waits for hosted mode (M3). — Why: local HTTP must bind loopback (spec §3, plan T25), which is unreachable from outside a container. — Cost if wrong: users who wanted HTTP in Docker wait for M3.
- Ruling E: T1 sets `.go-version` to `1.27.1` to match the toolchain the project now needs (go.mod will be ≥1.26). — Why: leaving 1.24.10 makes goenv point GOROOT at a toolchain that cannot build the module. — Cost if wrong: goenv users must run `goenv install 1.27.1`.
