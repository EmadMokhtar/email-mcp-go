# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish one site on GitHub Pages with a landing page, a user manual
and tech docs, and keep the docs true with a check on pull requests and with
screenshots made from the running program.

**Architecture:** Hugo builds `site/` with our own templates and no theme. A Go
test in `internal/e2e` starts the real program and takes the screenshots with
headless Chrome at build time. The images are not in git. Two small Go programs
in `test/` check the built site and the changed files of a pull request.
`release.yml` calls a new `pages.yml` workflow after a release succeeds.

**Tech Stack:** Hugo 0.169.0 (standard edition), Go, chromedp v0.21.0, GitHub
Actions, GitHub Pages.

**Spec:** Read the foundation first. Each task names its own spec too.

- `docs/superpowers/specs/2026-11-05-docs-site-foundation-design.md`
- `docs/superpowers/specs/2026-11-05-user-manual-design.md`
- `docs/superpowers/specs/2026-11-05-tech-docs-design.md`
- `docs/superpowers/specs/2026-11-05-landing-page-design.md`

## Global Constraints

- The site loads nothing from another site: no web fonts, no CDN, no script or
  style from outside. The site has no script at all.
- Colours, type and spacing come from `DESIGN.md`. No shadows, no gradients, no
  uppercase labels. Light and dark follow the setting of the computer.
- Content rules: no H1 in the body, H2 and H3 only, fenced code blocks with a
  language, alt text on images, lines of 80 characters.
- Front matter: `title`, `description`, `weight`. Manual and tech docs pages also
  have `code_areas`. `aliases` is allowed when a page moves.
- Language: short sentences, plain verbs, a definition after each technical term.
- Every fact comes from the code or an existing document. If they disagree, the
  code wins, and the difference is reported in the pull request.
- Invent nothing: no customers, quotes or numbers. `PRODUCT.md` says none exist.
- New text does not describe a weakness that is not fixed, and no text gives
  attack steps.
- Level 5 is "Delete", with the explanation that it moves mail to the Trash and
  never deletes mail for good.
- Sizes use the exact unit: "10 MiB" for a limit of `10 << 20` bytes.
- Workflows: read-only permissions by default, actions pinned by full commit SHA
  with the tag in a comment, and no `${{ }}` value inside a `run:` script.
- Shots: sample data only, on `example.com`. The web pages of email-mcp only.
- Each pull request has one GitHub issue assigned to `EmadMokhtar`, `Closes #N`
  in its body, and the assignee `EmadMokhtar`. Titles and commits use Conventional
  Commits: `docs:` for content, `ci:` for workflows, `test:` for test tools, and
  `build:` for the site setup. Never `feat:` or `fix:`, because those make
  release-please propose a release of the program.
- Commit messages end with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Pull request bodies
  end with `🤖 Generated with [Claude Code](https://claude.com/claude-code)`.

## Review Focus

1. **The site at a sub-path and at the root.** `/email-mcp-go/` today, `/` with a
   custom domain. A link written as `/manual/` must not leave the site. Test:
   `TestRootLinkFailsUnderBasePath` in Task 3, and `TestCheckPassesAtRoot`.
2. **A long command or a wide table on a phone.** At 375 pixels the page itself
   must not scroll sideways. Test: `TestNoSidewaysScroll` in Task 5.
3. **A secret in a picture.** A token, a sign-in link or a password must never
   reach an image. Test: `TestShotRefusesSecrets` in Task 5.
4. **Unusual pull requests.** Many files, a file moved out of `internal/`, a
   release pull request, a Dependabot pull request. The first two must be judged
   correctly, and the last two must not be blocked. Test: table in Task 22.
5. **No Chrome, a hung Chrome, or old images.** The run must stop fast with a
   clear message, and an image of a removed shot must not stay. Tests:
   `TestFindChromeNamesTheFix` and the time limit in Task 5, and the empty folder
   at the start of `TestScreenshots`.
